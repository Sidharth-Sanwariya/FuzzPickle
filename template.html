RecommendationsPrioritised by impact

  • 1. Never use pickle for untrusted models. Prefer safetensors, ONNX or GGUF. This removes the whole attack class instead of trying to filter it.
  • 2. Treat a scanner “SAFE” as “no known signature”, not as proof of safety. Nine files evaded every engine; one of them executed code.
  • 3. Fail closed. A crash, timeout or unsupported format must block the artifact, never pass it through.
  • 4. Layer defences. Combine scanners with a strict allow-list of importable globals, plus sandboxed loading (container, no network, read-only FS, dropped privileges).
  • 5. Block dangerous modules by default: os, subprocess, runpy, importlib, ctypes, pydoc, io, codecs, http.client, builtins.eval.
  • 6. Validate by content, not extension or magic bytes. .npy, .txt, .p and spoofed headers were all accepted as benign.
  • 7. Report upstream. Share these samples with scanner maintainers and re-run FuzzPickle after each release as a regression suite.

Methodology & caveatsRead before quoting these numbers

  • All files are treated as malicious test cases, so “SAFE” is a false negative and “DANGEROUS” is a true positive.
  • Only files marked with `EXECUTED` have execution confirmed. The others were not executed, so “blind spot” means “not flagged”, not “confirmed exploitable”.
  • The source report labels a Fickling CRASH as “flagged SAFE” in its Full Blind Spot wording. This dashboard keeps crash as its own category, which is more accurate. It does not change the headline: no engine raised an alert on those files.
  • Results reflect specific scanner versions and configuration on one run. Re-test after upgrades.
